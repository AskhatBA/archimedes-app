# Телемедицина: статичная услуга, цена 6000 ₸ и скрытые специальности

Slug: `telemedicine-static-service`. Дата: 2026-10-10.

## 1. Цель и контекст

Запрос заказчика (дословно):

> Если пользователь записывается на прием по "телемедицине" тогда нужно в booked_service
> отправлять статичный код "A02.083.000". Стоимость приема в телемедицине также статичная и
> должна быть равно 6000 тенге. Также в телемедицине нужно убрать специалистов (чтобы их не
> было видно в списке): 1. врачей УЗИ 2. массажистов 3. стоматолога 4. выездной службы
> 5. психолога 6. рентгенолога

Зачем: онлайн-консультация — одна услуга клиники с одним кодом и одной ценой, независимо от
того, какой врач её ведёт. Сейчас в МИС уходит услуга очного приёма врача, а пациент платит
цену очного приёма (со скидкой медсчёта), то есть телемедицина учитывается и оплачивается
как обычный визит.

### 1.1 Как устроено сейчас

**Признак телемедицины.** `CreateAppointmentForm.isTelemedicine` (`src/modules/appointment/types.ts`),
переключается `AppointmentTypeSwitch` в `create-appointment-form.tsx` (при переключении
сбрасывается только `specializationId`). Уходит:
- в `POST /mis/create-appointment` как `isTelemedicine` (приём по программе);
- в `POST /payment/init` (`purpose: 'APPOINTMENT'`) как `metadata.isTelemedicine` (платный приём).

На бэкенде `mis.service.createAppointment` для телемедицины создаёт Zoom-встречу и передаёт в
МИС `is_telemedicine`; `Appointment.isTelemedicine` пишется в нашу таблицу.

**`booked_service`.** Добавлен коммитами b4d93a0 (app) / 8f8dfaf (backend). Сейчас это `oid`
услуги врача из `GET /insurance/medic-service` (UUID страховой), который приложение шлёт как
`medicServiceOid`:
- `mis.controller.createAppointment` → `misService.createAppointment({ medicServiceOid })`;
- `appointment.payment-handler.ts` хранит `medicServiceOid` в метаданных платежа и после
  оплаты вызывает тот же `misService.createAppointment`;
- `mis.service.ts`: `booked_service: newAppointment.medicServiceOid` (единственная точка).
- Тот же `medicServiceOid` уходит кодом позиции в фискальный чек
  (`fiscal.positions.ts → appointmentPositions`).

**Цена.** `CreateAppointmentContext.visitPrice`:
- платный приём (нет программы): `medicService.price` + скидка `priceMedAccount` из
  `GET /insurance/service-price` (`useServicePrice`); списывается
  `discountedPrice ?? price`;
- приём по программе `isMedAccount`: цена страховой (`servicePrice`), через нас ничего не
  списывается;
- прочие программы: цены нет.
`AppointmentPrice` показывает `medicService.service` и `visitPrice`. Бэкенд сумму платежа
`APPOINTMENT` **не проверяет** — она клиентская (так прямо записано в backend CLAUDE.md).

**Список специалистов.** `useSpecializations` (`src/modules/appointment/hooks/use-specializations.ts`)
берёт `GET /mis/specializations?branchId=` (прокси МИС
`/beneficiary/branches/:branchId/specialties/`, элементы `{ id, name }`) и фильтрует **на
клиенте по подстроке названия**:
- всегда исключены `УЗИ`, `ВЫЕЗДНАЯ СЛУЖБА`, `МАССАЖ` (`toUpperCase().includes`);
- **для телемедицины остаются только специальности, в названии которых есть `'Терапевт'`**
  (белый список, регистрозависимо).

Врачи (`useDoctors`, `GET /mis/doctors`) запрашиваются уже по выбранной специальности, у
врача есть `specialtyName` и `position`, но сейчас по ним ничего не фильтруется.

> Важно: при нынешнем белом списке «Терапевт» ни одна из шести перечисленных категорий в
> телемедицине и так не видна. **Решение заказчика (OQ-1): белый список заменяется чёрным —
> в телемедицине видны все специальности, кроме шести.**

## 2. Решение и обоснование

### 2.1 Код услуги — только на бэкенде

`booked_service` подставляется в единственной точке, `mis.service.createAppointment`:
`isTelemedicine ? config.telemedicine.serviceCode : medicServiceOid`. Через неё проходят оба
пути записи (по программе и после оплаты), и правка сразу работает для **уже установленных
сборок приложения** без релиза. Приложение код не знает и не шлёт.

### 2.2 Цена — задаёт и проверяет бэкенд, приложение показывает

Сумма — это деньги, поэтому источник правды — бэкенд, как у пополнения медсчёта и чек-апов:
- `config.telemedicine.price` (6000) отдаётся приложению новым эндпоинтом, приложение её не
  хардкодит — смена цены не требует релиза;
- `beforePayment` назначения `APPOINTMENT` отказывает в оплате телемедицины на любую другую
  сумму, пока карта пациента не списана (тот же приём, что `MED_ACCOUNT_TOPUP_AMOUNT_MISMATCH`
  и `PROGRAM_ORDER_PRICE_CHANGED`). Так устаревшая цена на устройстве или старая сборка не
  приводит к списанию «не той» суммы.

Отвергнутые варианты: хардкод 6000 в приложении без серверной проверки (сумма `APPOINTMENT`
останется клиентской, старые сборки продолжат брать цену очного приёма); молча подменять
сумму на сервере (пациент заплатил бы не то, что видел).

Для телемедицины `medic-service` и `service-price` больше не нужны: цена и название услуги не
зависят от врача. Это заодно убирает зависимость записи на онлайн-приём от ответа страховой.

### 2.3 Фильтр специальностей — на бэкенде, конфигурируемый

`GET /mis/specializations` получает необязательный `isTelemedicine=true` и выкидывает
специальности по списку подстрок из конфига. Почему бэкенд:
- список придётся уточнять по мере появления новых специальностей в МИС — правка env без
  релиза в сторы (реальные названия сверены, см. OQ-2);
- старые сборки параметр не шлют и продолжают показывать только терапевтов — безопасно.
Общие исключения (УЗИ/выездная/массаж для любого типа приёма) остаются в приложении как
есть — их перенос вне объёма задачи.

Серверная проверка специальности при создании телемед-записи (лишний запрос
`/beneficiary/doctors/:id/` в МИС на каждую запись) в объём **не входит** — это UX-фильтр, а
не защита денег; см. OQ-9.

### 2.4 К каким сценариям что применяется

| Сценарий телемедицины | `booked_service` | Цена в форме | Списание через нас |
|---|---|---|---|
| Платный (без программы) | `A02.083.000` | 6000 ₸, без скидки медсчёта | 6000 ₸, проверяется сервером |
| Программа `isMedAccount` | `A02.083.000` | не показывается | нет (списывает страховая) |
| Прочая страховая программа | `A02.083.000` | не показывается | нет |
| Для родственника по программе | `A02.083.000` | как у программы | нет |

Очный приём (`isTelemedicine: false`) не меняется ни в чём.

## 3. Пользовательские сценарии

1. **Платная онлайн-консультация.** Пациент без программы выбирает «Телемедицина», филиал;
   в списке специальностей нет УЗИ, массажа, стоматологии, выездной службы, психолога,
   рентгенолога. Выбирает врача — карточка цены показывает «Онлайн-консультация врача —
   6 000 ₸» без зачёркнутой цены. Принимает оферту, платит 6000 ₸. После оплаты запись
   создаётся в МИС с `booked_service = "A02.083.000"`; чек — на 6000 ₸ (логика чека не
   меняется).
2. **Онлайн-консультация по программе медсчёта.** Цены нет, кнопка «Записаться» не ведёт в
   оплату; запись в МИС — с тем же кодом.
3. **Онлайн-консультация по страховой программе.** Цены нет; запись с тем же кодом.
4. **Переключение типа приёма.** Пациент выбрал очный приём, специальность, врача и слот,
   затем переключился на телемедицину — специальность, врач и слот сбрасываются, список
   специальностей перечитывается для телемедицины.
5. **Цена изменилась, пока форма была открыта / старая сборка.** Сервер отказывает в
   инициализации оплаты, пациент видит тост с причиной, деньги не списаны.

## 4. Изменения

### 4.1 Backend (`../archimedes-backend`)

Миграций Prisma **нет**: ни одна таблица не меняется (`Appointment.isTelemedicine` уже есть,
сумма — в `Payment.amount`, код уходит только в МИС).

**Конфиг** — `src/config/index.ts`, новый блок `telemedicine`:

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `TELEMEDICINE_SERVICE_CODE` | `A02.083.000` | значение `booked_service` для любой телемед-записи |
| `TELEMEDICINE_PRICE` | `6000` | цена онлайн-консультации, ₸ (через `numberFromEnv`) |
| `TELEMEDICINE_EXCLUDED_SPECIALTIES` | `УЗИ,МАССАЖ,СТОМАТОЛОГ,ВЫЕЗДН,ПСИХОЛОГ,РЕНТГЕН` | подстроки названий специальностей, скрытых в телемедицине (сравнение без учёта регистра) |

Добавить переменные в `.env.example`.

**`src/domains/mis/mis.service.ts` — `createAppointment`:**
`booked_service: newAppointment.isTelemedicine ? config.telemedicine.serviceCode : newAppointment.medicServiceOid`.
Клиентский `medicServiceOid` для телемедицины игнорируется (не ошибка — старые сборки его
шлют). Обновить JSDoc у `CreateAppointmentDto.medicServiceOid` (`mis.dto.ts`) и описание
поля в swagger `mis.routes.ts`.

**`src/domains/mis/mis.controller.ts` — `getSpecializations` / `mis.service.ts`:**
- принять необязательный query `isTelemedicine` (`'true'`/`'false'`, `isBoolean`);
- при `true` отфильтровать результат `getSpecializationsByBranchId`: убрать элементы, у
  которых `name.toUpperCase()` содержит любую подстроку из
  `config.telemedicine.excludedSpecialties` (подстроки тоже приводятся к верхнему регистру);
- без параметра или при `false` — ответ байт-в-байт как сейчас;
- swagger: описать параметр.

**`src/domains/appointments/appointment.payment-handler.ts`:**
- `beforePayment` (`ensureBookable` или новая обёртка): если `metadata.isTelemedicine` и
  `amount !== config.telemedicine.price` → `AppError(APPOINTMENT_TELEMEDICINE_PRICE_MISMATCH_MESSAGE, 409)`
  **до** проверки конфликтов; лог `warn` с `amount` и ожидаемой ценой;
- сообщение — человекочитаемая константа рядом с
  `APPOINTMENT_SAME_DOCTOR_SAME_DAY_MESSAGE`, потому что и текущая, и старые сборки
  показывают `response.data.message` платного флоу как есть:
  `'Стоимость онлайн-консультации изменилась. Обновите страницу записи и попробуйте снова.'`;
  выключателя проверки на переходный период **нет** (OQ-7);
- `validateMetadata` не меняется (`medicServiceOid` для телемедицины может прийти от старых
  сборок и просто не используется для `booked_service`).

**Фискальный чек (`fiscal.positions.ts`) не меняется** (OQ-8: на нашей стороне код в чеке
пока не нужен). Новая сборка не шлёт `medicServiceOid` для телемедицины, поэтому у позиции
телемед-чека кода не будет — `code` и так необязательный.

**Новый эндпоинт `GET /v1/api/appointments/telemedicine`** (`appointments.routes.ts`,
`authenticate`, `asyncHandler`, **зарегистрировать до `/:id`**):

```json
{ "success": true, "telemedicine": { "price": 6000, "serviceName": "Онлайн-консультация врача" } }
```

`serviceName` — та же строка, что `POSITION_NAMES.telemedicine` (вынести в общую константу,
чтобы форма и чек называли услугу одинаково; сам чек не трогать). Код услуги приложению не отдаётся — он ему не нужен.
Swagger + DTO в `appointments.dto.ts`.

**`CLAUDE.md` бэкенда:** раздел «Telemedicine» — код, цена, проверка суммы, фильтр
специальностей, переменные окружения; поправить фразу в «Med-account visit price» о том,
что сумма `APPOINTMENT` никогда не проверяется (для телемедицины теперь проверяется).

### 4.2 App (этот репозиторий)

**API.** `src/api/appointment-api.ts` (рукописный клиент) — `telemedicineDetail()` →
`GET /appointments/telemedicine`, тип `TelemedicineOffer { price: number; serviceName: string }`.
Параметр `isTelemedicine` у `misApi.specializationsList` появляется после
`npm run generate-api` против обновлённого бэкенда (файлы `src/api/generated/` руками не
править) — ещё одна причина выкатывать бэкенд первым.

**Хуки.**
- новый `useTelemedicineOffer(enabled)` в `src/modules/appointment/hooks/` — `useQuery`
  (`queryKey: ['appointments', 'telemedicine']`, `staleTime: 0` или короткий — цена должна
  совпасть с серверной в момент оплаты), включается только при `isTelemedicine`;
- `useSpecializations(branchId, isTelemedicine)` — шлёт `isTelemedicine` в запрос,
  `queryKey: ['specializations', branchId, !!isTelemedicine]`, **удаляет белый список
  `'Терапевт'`** (если OQ-1 подтвердит), общий `EXCLUDED_SPECIALIZATIONS` оставляет для обоих
  режимов;
- `useMedicService` — добавить `enabled`; в контексте выключать для телемедицины;
  `useServicePrice` — `enabled` уже есть, передавать `false` для телемедицины.

**`CreateAppointmentContext`** (`src/modules/appointment/context/create-appointment-context.tsx`):
- `visitPrice` для телемедицины: только при платном приёме (без программы) —
  `{ price: offer.price, discountedPrice: null, serviceName: offer.serviceName }`, пока
  `offer` не загружен — `null`; для **любой** программы, включая `isMedAccount`, — `null`
  (цена показывается только платным, OQ-4/OQ-6); `useTelemedicineOffer` включается только
  для платного телемед-приёма. Для очного приёма — как сейчас
  (`serviceName: medicService.service`). Расширить `VisitPrice` (`types.ts`) полем
  `serviceName`, чтобы карточка цены не зависела от `medicService`. Расчёт вынести в чистую
  функцию `src/modules/appointment/lib/visit-price.ts` и покрыть тестом;
- `initAppointmentPaymentMutation` для телемедицины: `amount = visitPrice.price`,
  `description` и `metadata.serviceName` = `visitPrice.serviceName`, `medicServiceOid` не
  отправлять; проверка `if (!medicService || !visitPrice)` — для телемедицины только
  `visitPrice`;
- `createAppointmentMutation` для телемедицины: `medicServiceOid` не отправлять;
- `isBookingEnabled` — без изменений по смыслу: платный приём ждёт `visitPrice`.

**Форма** (`create-appointment-form.tsx`): при смене типа приёма сбрасывать
`specializationId`, `doctorId`, `timeSlot` (сейчас только `specializationId`, и
`isBookingEnabled` может снова стать `true` со старым врачом из другой специальности).

**`AppointmentPrice`**: условие показа — `formValues.doctorId && visitPrice`; название услуги —
`visitPrice.serviceName`.

**i18n** (`ru.json`, `kk.json`, `en.json`, `appointments:create`):
`errorTelemedicineOffer` — «Не удалось загрузить стоимость онлайн-консультации. Попробуйте
позже.»

**`CLAUDE.md` приложения:** в «Med-account visit price» — абзац о телемедицине (цена и
название с бэкенда, без скидки медсчёта, без `medic-service`), в описании формы — что фильтр
специальностей телемедицины делает бэкенд.

Экраны и `routes.*` не добавляются.

## 5. Критерии приёмки

Backend
- **AC-1.** Запись `POST /mis/create-appointment` с `isTelemedicine: true` уходит в МИС с
  `booked_service: "A02.083.000"` независимо от присланного `medicServiceOid` (и при его
  отсутствии).
- **AC-2.** Платная запись после успешной оплаты с `metadata.isTelemedicine: true` уходит в МИС
  с `booked_service: "A02.083.000"`, в том числе если в метаданных есть `medicServiceOid`.
- **AC-3.** Запись с `isTelemedicine: false` уходит с `booked_service = medicServiceOid`, как
  до изменений.
- **AC-4.** `POST /payment/init` с `purpose: APPOINTMENT`, `metadata.isTelemedicine: true` и
  `amount: 6000` проходит; с любой другой суммой — 409 с сообщением
  `APPOINTMENT_TELEMEDICINE_PRICE_MISMATCH_MESSAGE`, запись `Payment` не создаётся, в
  FreedomPay ничего не уходит.
- **AC-5.** Для `isTelemedicine: false` сумма `APPOINTMENT` по-прежнему не проверяется.
- **AC-6.** `GET /v1/api/appointments/telemedicine` с валидным токеном отвечает 200
  `{ success: true, telemedicine: { price: 6000, serviceName: "Онлайн-консультация врача" } }`;
  без токена — 401; маршрут не перехватывается `GET /appointments/:id`.
- **AC-7.** Значения кода, цены и списка исключений меняются переменными
  `TELEMEDICINE_SERVICE_CODE`, `TELEMEDICINE_PRICE`, `TELEMEDICINE_EXCLUDED_SPECIALTIES` без
  правки кода; AC-1, AC-4, AC-6 следуют новым значениям.
- **AC-8.** `GET /mis/specializations?branchId=X&isTelemedicine=true` не содержит ни одной
  специальности, название которой (без учёта регистра) содержит `УЗИ`, `МАССАЖ`,
  `СТОМАТОЛОГ`, `ВЫЕЗДН`, `ПСИХОЛОГ`, `РЕНТГЕН`; прочие специальности филиала присутствуют.
- **AC-9.** `GET /mis/specializations?branchId=X` без `isTelemedicine` и с
  `isTelemedicine=false` отвечает тем же списком, что и до изменений.
- **AC-10.** `fiscal.positions.ts` не изменён; чек продажи за телемед-приём по-прежнему
  содержит одну позицию на сумму платежа.

App
- **AC-11.** В режиме «Телемедицина» список специальностей не содержит шести категорий из
  AC-8 и содержит остальные специальности филиала, кроме общих исключений (УЗИ, выездная
  служба, массаж). Белого списка «Терапевт» больше нет.
- **AC-12.** В режиме «Обычный» список специальностей не изменился.
- **AC-13.** Переключение типа приёма сбрасывает специальность, врача и выбранный слот;
  кнопка записи становится неактивной до нового выбора.
- **AC-14.** Платный телемед-приём: карточка цены показывает `serviceName` и `price` из
  `GET /appointments/telemedicine` (6 000 ₸) без зачёркнутой цены; запросы
  `/insurance/medic-service` и `/insurance/service-price` для телемедицины не выполняются.
- **AC-15.** Платный телемед-приём: `POST /payment/init` отправляется с `amount` = цене из
  карточки (6000), `description` и `metadata.serviceName` = `serviceName`, без
  `medicServiceOid`.
- **AC-16.** Платный телемед-приём: кнопка «Записаться и оплатить» неактивна, пока цена
  телемедицины не загружена; при ошибке загрузки показывается тост
  `appointments:create.errorTelemedicineOffer`, кнопка остаётся неактивной.
- **AC-17.** Телемед-приём по программе `isMedAccount`: карточка цены показывает цену из

- **AC-20.** Очный приём (платный, по медсчёту, по программе) ведёт себя как до изменений:

## 6. Краевые случаи и ошибки

| Ситуация | Поведение |
|---|---|
| Старая сборка, платный телемед, сумма ≠ 6000 | 409, тост с текстом сообщения (сборка показывает `message` как есть), деньги не списаны. Выключателя нет (OQ-7). |
| Старая сборка, телемед по программе | Запись проходит, `booked_service` уже статичный (AC-1). |
| Цена изменилась в env, пока форма открыта | Сервер отказывает (AC-4); после повторного открытия формы `useTelemedicineOffer` подтянет новую цену. |
| `GET /appointments/telemedicine` упал | Платный телемед нельзя оплатить (AC-16); телемед по любой программе не затронут — эндпоинт для него не запрашивается. |
| Новая сборка против старого бэкенда | Параметр `isTelemedicine` игнорируется — в телемедицине видны все специальности, `/appointments/telemedicine` → 404. **Порядок выкатки: сначала бэкенд.** |
| `medic-service` для врача не отвечает | На телемедицину не влияет (не запрашивается). |
| Конфликт «тот же врач в тот же день» | Без изменений; проверка цены (AC-4) идёт раньше конфликтов. |
| Отмена платного телемед-приёма | Без изменений: возврат считается от `paidAmount` (6000), 100% / 70%. |
| Новая специальность в МИС с названием вне шаблонов | Останется видна — шаблоны уточняются env-переменной. |

Коды/тексты ошибок: новое сообщение `APPOINTMENT_TELEMEDICINE_PRICE_MISMATCH_MESSAGE` (409);
новый ключ i18n `appointments:create.errorTelemedicineOffer`. Существующие
`appointments:create.errorPaymentInit` / `errorUnknown` — без изменений.
